# FluxMesh 流量面架构

## 1. 范围

流量面读取服务配置。
流量面创建本地监听。
流量面代理 L7 HTTP、L4 TCP 和 L4 UDP。

流量面不劫持主机流量。
流量面也不使用 Envoy。
每个 FluxMesh 节点独立运行流量面。

## 2. 组件

| 组件 | 职责 |
| --- | --- |
| `ServiceConfig` | 声明路由、后端和策略 |
| `registry.Services` | 从 etcd 读取服务配置 |
| `BuildPlan` | 编译监听、路由和目标索引 |
| `traffic.Server` | 收敛监听并代理流量 |
| 管理接口 | 显示 L7 计划、模拟匹配和读取统计 |

## 3. 运行计划

运行计划包含以下内容：

- L7 HTTP 监听和路由表
- L4 TCP 监听绑定
- L4 UDP 监听绑定
- 后端组和选择策略
- 服务名到监听的索引
- 本节点的轮询和时延状态

L7 服务可共享相同 TCP 监听。
它们使用 Host 和 Path 匹配。
每个 L4 监听只绑定一个同协议服务。

TCP 和 UDP 属于不同传输协议。
它们可使用相同数字端口。

## 4. 配置收敛

启动时，流量面读取全部服务配置。
初次编译失败会阻止应用启动。

启动后，etcd Watch 触发刷新。
Watch 断开后，流量面等待 1 秒重连。
每 30 秒还有一次兜底刷新。

流量面用服务名和版本生成快照。
快照未变化时，刷新直接返回。
编译失败时，旧计划继续生效。

新增监听失败时，运行时只写日志。
配置版本变化后，运行时才会再次尝试。

## 5. L7 HTTP 链路

1. 请求进入 L7 监听。
2. 计划按 Host 和 Path 匹配。
3. 计划解析 `destination`。
4. 策略生成上游候选。
5. 运行时转发请求。
6. 状态码不小于 502 时重试。
7. 运行时更新本地统计。

精确 Host 优先于通配 Host。
长 Path 前缀优先于短前缀。
相同条件下，路由权重决定顺序。

## 6. L4 TCP 链路

1. 连接进入 TCP 监听。
2. 计划读取该监听的唯一绑定。
3. 计划生成上游候选。
4. 运行时依次尝试建立连接。
5. 成功后双向复制字节流。

TCP 只在建连失败时换候选。
已建立连接不会中途迁移。

## 7. L4 UDP 链路

1. 报文进入 UDP 监听。
2. 计划读取该监听的唯一绑定。
3. 计划生成上游候选。
4. 运行时写入上游并等待响应。
5. 运行时把响应写回客户端。

会话键包含监听、客户端和上游。
运行时按会话 TTL 复用 UDP 连接。
每 5 秒清理一次过期会话。

## 8. 状态边界

服务配置来自 etcd。
流量计划保存在进程内存中。
轮询计数和时延 EWMA 也在本地。

SoftKV 当前不参与上游选择。
不同节点可能选择不同上游。
进程重启会清空选择状态。

## 9. 管理接口边界

`/api/v1/traffic/plan` 只返回 L7 监听。
该接口不返回 TCP 和 UDP 绑定。

`/api/v1/traffic/match` 只模拟 L7 匹配。
该接口不验证监听是否成功绑定。

`/api/v1/traffic/stats` 只统计 L7 请求。
TCP 和 UDP 流量不进入该统计。

## 10. 当前限制

- 没有 TLS 终止配置。
- 没有 SNI 路由。
- 没有连接级熔断。
- 没有主动健康检查。
- 没有请求体大小限制。
- 重试不判断 HTTP 方法是否幂等。
- Relay 只表示候选分类。
- Relay 不执行全局路径搜索。
